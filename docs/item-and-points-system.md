# ระบบไอเท็มและแต้มวังหลัง

เอกสารนี้เป็นกติกากลางของเว็บผู้เล่น (`lanzhou-player`), เว็บทีมงาน
(`palace-ledger-v2`) และ Supabase เพื่อให้การทำงาน OOC มีคำอธิบาย IC ตรงกัน

## หน่วยแต้ม

- **RP** เป็นแต้มใช้จ่าย ได้จากการส่งโรล กิจกรรม ภารกิจ งานสร้างสรรค์ และการสำรวจ
- **โปรดปราน** ใช้กับการเลื่อนตำแหน่ง การเข้าถึง และการปรับแต้มตามกติกาของทีมงาน
- ผู้เล่นสามารถถวาย 10 RP เพื่อรับ 1 โปรดปรานได้จากปุ่ม `+` ข้างคะแนนโปรดปราน
- ทีมงานปรับรางวัลรายชิ้นได้ แต่อัตราเริ่มต้นมาจาก `rp_reward_guidelines`

| ประเภทผลงาน | RP แนะนำ | โปรดปรานแนะนำ |
| --- | ---: | ---: |
| โรลเพลย์ | 8 | 1 |
| เข้าร่วมกิจกรรม | 10 | 1 |
| งานวาด / งานสร้างสรรค์ | 6 | 0 |
| ภารกิจ | 8 | 1 |
| สำรวจ | 5 | 0 |
| อื่น ๆ | 5 | 0 |

ราคาเริ่มต้นแบ่งเป็นช่วงเพื่อให้ผู้เล่นใหม่ประเมินเวลาเก็บแต้มได้:

- ของใช้พื้นฐานในวัง: 0–8 RP
- ของถูกกฎจากนอกวัง: 15–40 RP
- ของต้องห้าม: 60–120 RP พร้อมเงื่อนไขโปรดปราน การปลดล็อก และความเสี่ยง
- ของเนื้อเรื่อง: ไม่มีราคาและซื้อไม่ได้

ยอด RP เดิมของตัวละครไม่ถูกรีเซ็ต เพราะอาจเป็นยอดจากระบบก่อนหน้า ทีมงานควรใช้ช่วงราคา
ข้างต้นกับไอเท็มใหม่ และพิจารณาไอเท็มจำกัดจำนวนสำหรับการระบายยอดสะสมเก่า

## เส้นทางการได้รับ

```text
ของในวัง
ผู้เล่น → เบิกจากแคตตาล็อก → ตรวจ RP/สต็อก → เข้าคลังตัวละคร

ของถูกกฎจากนอกวัง (ตำแหน่งทั่วไป)
ผู้เล่น → ระบบหัก RP และกำหนดวันรับ → หน่วยจัดซื้อ → เปิดเว็บหลังครบกำหนด → เข้าคลัง

ของถูกกฎจากนอกวัง (ตำแหน่งที่มีสิทธิ์)
ผู้เล่น → ออกคำสั่งจากตำหนัก/หน่วยงาน → ระบบหัก RP และกำหนดวันรับ
→ ผู้รับใช้ที่ได้รับอนุญาตจัดซื้อ → เปิดเว็บหลังครบกำหนด → เข้าคลัง

ของต้องห้าม
ผู้เล่น → ปลดล็อกเบาะแสเฉพาะตัวละคร → ติดต่อคนกลาง → ทีมงานอนุมัติและหัก RP
→ ทอยความเสี่ยง → สำเร็จ: จัดหาและส่งมอบ / ล้มเหลว: สรุปผลและคืน RP

ของเนื้อเรื่อง
สำรวจ/อีเวนต์/ภารกิจ → ผ่านเงื่อนไข → ทีมงานมอบเข้าคลังโดยตรง
```

สิทธิ์ “ออกคำสั่งให้จัดซื้อ” อิงตำแหน่งจาก
`character_position_acquisition_privileges` ไม่อิงจำนวนโปรดปราน เพื่อไม่ให้ตัวละครชั้นผู้น้อย
ที่สะสมแต้มสูงข้ามลำดับการใช้อำนาจในเนื้อเรื่อง

ของถูกกฎจากนอกวังไม่เข้าคิวทีมงาน ระบบบันทึก `available_at` และเรียก
`process_due_item_deliveries` เมื่อผู้เล่นเปิดเว็บ จึงไม่ใช้ Cron หรือ Edge Function และไม่มีงานเบื้องหลัง
ขณะไม่มีผู้ใช้งาน

## คนกลางของช่องทางลับ

ช่องทางเริ่มต้นคือ **หลัวจิ้ง — เสมียนบัญชีรถส่งเสบียงประจำประตูฝ่ายใน**

- เข้าถึงของได้เพราะตรวจบัญชีรถส่งเสบียงและใบผ่าน จึงซ่อนห่อเล็กมากับของที่ได้รับอนุญาตได้
- แรงจูงใจคือเงินชำระหนี้ครอบครัวและการสะสมข้อมูลไว้ต่อรองเพื่อเอาตัวรอด
- ความลับคือเคยแก้บัญชีให้ผู้มีอำนาจ หากบัญชีเก่าถูกพบจะเสียตำแหน่งและชีวิต
- ปลดล็อกโดยพบเบาะแสบัญชีส่งเสบียง ช่วยปิดร่องรอย หรือได้รับการแนะนำจากผู้ติดต่อที่ไว้ใจได้
- สิทธิ์ปลดล็อกผูกกับตัวละครและไอเท็ม ทีมงานต้องบันทึกที่มาทุกครั้ง

ทีมงานเห็นข้อมูล NPC ทั้งหมด ผู้เล่นเห็นชื่อ บทบาท และความเสี่ยงหลังปลดล็อกเท่านั้น

## ระบบทอย

การจัดหาของต้องห้ามใช้ d100 หนึ่งครั้ง สรุปขั้นตอนติดต่อและลักลอบเป็นการทอยเดียว
เพื่อลดภาระทีมงาน ส่วนการนำไอเท็มไปใช้ยังใช้ระบบคำร้องใช้ไอเท็มเดิมแยกต่างหาก

- 1–5: สำเร็จอย่างยอดเยี่ยม
- 6 ถึงค่าโอกาสสำเร็จของไอเท็ม: สำเร็จ
- มากกว่าค่าโอกาสสำเร็จ แต่ต่ำกว่า 96: ล้มเหลว
- 96–100: ล้มเหลวร้ายแรง

ผลสำเร็จไปสถานะ `procuring` ผลล้มเหลวไป `risk_review` เพื่อให้ทีมงานบันทึกผล IC
ก่อนปิดคำร้องและคืน RP ระบบไม่ให้ทอยซ้ำในคำร้องเดิม

การทอยตอนใช้ของ เช่น วางยา ตรวจพิษ ปลอมตรา หรือใช้กับตัวละครอื่น ยังคงผ่าน
`item_use_requests` และกติกา `requires_roll` ของไอเท็ม จึงไม่ปะปนกับการทอยจัดหา

## สถานะคำร้องจัดหา

```text
submitted
  ├─ ไม่อนุมัติ → rejected
  └─ อนุมัติ
       ├─ ต้องทอย → awaiting_roll
       │    ├─ สำเร็จ → procuring
       │    └─ ล้มเหลว → risk_review → rejected
       └─ ไม่ต้องทอย → procuring

procuring → ready → completed
```

RP และสต็อกถูกกันเมื่อทีมงานอนุมัติ ไม่ใช่ตอนผู้เล่นส่งคำร้อง หากปิดเป็น
`rejected` หรือ `cancelled` ระบบคืน RP และสต็อกที่กันไว้ให้อัตโนมัติ ไอเท็มเข้าคลังเฉพาะ
เมื่อสถานะเป็น `completed`

## สิ่งที่เก็บ ปรับ และแทนที่

- **เก็บ:** ตารางไอเท็ม คลังตัวละคร ธุรกรรมสต็อก ระบบใช้ไอเท็ม ระบบสำรวจ และคิวตรวจ RP
- **ปรับ:** หน้าเดิมจากร้านค้าเป็นแคตตาล็อก, โปรดปรานเป็นเกณฑ์สะสม, การจัดซื้อภายนอกตามตำแหน่ง,
  และการให้รางวัล RP ตามตารางกลาง
- **แทนที่:** การซื้อไอเท็มทุกชนิดแบบทันที ถูกแทนด้วยเส้นทางเบิก/จัดซื้อ/ช่องทางลับ/มอบโดยทีมงาน
- **ห้ามทำ:** ของต้องห้ามเป็นของคลังสาธารณะ, ใช้โปรดปรานเป็นเงิน, หรือให้ของเนื้อเรื่องซื้อจากแคตตาล็อก

## ขอบเขตความปลอดภัยที่ยังแยกจากงานนี้

เว็บผู้เล่นเดิมเข้าสู่ระบบด้วย username และเก็บ `characterId` ใน localStorage จึงยังไม่ใช่การยืนยัน
ตัวตนที่ปลอดภัยสำหรับระบบเปิดสาธารณะ การเปลี่ยนเป็น Supabase Auth และผูกผู้ใช้กับตัวละครควรเป็นงาน
แยกก่อนเปิดใช้งานกับข้อมูลจริง แต่ไม่ควรปะปนกับกติกาเศรษฐกิจและเส้นทางไอเท็มชุดนี้
